## Fix direction

### U4-1: oversize `combatants_added` event on a large rolled start
- **Root cause:** the audit event of a start keeps every monster's dice faces in one JSON payload bounded by a 4 KiB CHECK; nothing limits the payload to what fits.
- **Where:** `joinStart` (`combat_monsters.go`). Alternatives: (a) split into several `combatants_added` events of at most about 15 monsters each (same shape, undo and log already read the event per batch, trade-off: more events); (b) drop `Faces`/`Dice` from the stored items and keep only id + hit points (smaller, but the master's line "Bandido 1: 2d8+2 (5, 3) = 11 PV" loses the faces). Pick (a): it keeps what the master sees.
- **Same pattern elsewhere:** any event that lists per-combatant data: `AddCombatants` (`combat.go:1042`, small), `CastSpell` cast event (`maxSpellTargets = 10` guards it), `monstersEvent` in `AddMonsters` (max 10), trap firings with many caught creatures: this is U4-12 (confirmed, 8 creatures).
- **Rules:** `docs/architecture.md` says a session event payload is at most 4 KiB; an over-limit client request must be `invalid_argument`/`failed_precondition`, never `internal`; a retry with the same idempotency key must still return the first answer. Update the "Encounter builder (MR-043)" and "Monsters in combat" sections.
- **Risk:** the log (`combat_log.go` MONSTERS_ADDED) and the undo read `ev.Monsters`; guard tests: `TestMR043_*`, `combat_monsters_test.go`, `idempotency_test.go`.

### U4-8: 40001 hidden from `db.InTx` by `dbError`
- **Root cause:** functions that take the caller's `tx` translate the pg error to a Connect error (`rpcerr.FromDB`) before returning, destroying the wrapped `*pgconn.PgError` that `db.InTx` uses to retry.
- **Where:** every tx-taking roster read in `characters` (list in the finding row; `characters/errors.go:105-115` `dbError`): when a `tx` was passed, return `wrap(what, err)` / `fmt.Errorf("...: %w", err)` and let the RPC boundary translate after `InTx`. Alternative: make `rpcerr.FromDB` keep the pg error as the cause of the Connect error (`connect.NewError` with `errors.Join`/wrapping) so `errors.As` still finds it; one change covers every caller but changes a shared package. Pick the first for the characters module (matches the rule already written in the `InTx` doc comment), and consider the second as a safety net.
- **Same pattern elsewhere:** `characters/combatants.go`, `combatmonsters.go`, `combatturn.go`, `mapcharacters.go:34`, `npcportraits.go:32`, `partyvision.go`, `wildshape.go:97-121`, `progress.go`, `approval.go`, `portrait.go`; `progression/award.go`, `milestones.go`, `undo.go` call `s.dbError` inside their own `InTx` closures (not individually confirmed); `maps` and `campaigns` unaudited.
- **Rules:** one-connection rule and the "a read error inside the transaction propagates, wrapped with `%w`" row of `docs/architecture.md` "Transactions and the connection pool"; the error-code table.
- **Risk:** error text and codes of the RPCs for non-retryable errors must stay the same; guard tests: each module's `dbError` tests, `TestReview4_RosterReadInside*`.

### U4-5: reveal brings back a hidden NPC's old trap line
- **Root cause:** the trap event stores no per-creature "hidden at the time" flag; the log decides visibility from the current `combatants.hidden`.
- **Where:** `trapCaughtEvent` (`combat_traps.go`): add `Hidden bool` set in `fireInCombat` from `who.Hidden` when written; `trapEntry`'s `hidden` closure (`combat_log.go:679`) returns true if the event stamped it hidden OR it is hidden now. Alternative: stamp `Secret` on the whole event when any caught creature is hidden (simpler, but hides the visible creatures' lines too). Pick the per-creature stamp.
- **Same pattern elsewhere:** every event that judges visibility at read time on a non-fog map instead of from a stamp: check the other `hiddenFrom`/`v.sees` uses in `combat_log.go` for events created by `combat_conditions.go`, `combat_reactions.go`, `traps_fire.go` (manual firing by the master, `traps_fire.go:145,208`), and out-of-combat `traps_activity.go`.
- **Rules:** RN-10; `combat_log.go` header ("a combatant the master reveals later does not bring its old entries"); events carry ids and numbers only (docs/privacy.md).
- **Risk:** older stored events have no stamp: treat missing as "not hidden then". Guard tests: `TestRN10_FogCombatATrapThatCaughtAnNPCOutOfSight...`, `TestRN20_PlayersNeverReceiveCAOrHiddenLogEntries`.

### U4-7: out-of-combat trap damage bypasses Wild Shape
- **Root cause:** `settleTrapDamage` has its own copy of the damage arithmetic instead of the beast-aware `damageBeast` path.
- **Where:** `traps_damage.go:187-197`: when `now.GetWildShape() != nil`, call `damageBeast` (needs a `combatTx`-less variant: factor the pure part of `damageBeast` that builds the `AdjustCharacterVitalsRequest` and the form end out of `wildshape.go`). Alternative: route out-of-combat trap damage through `ApplyPendingDamage`. Pick the shared helper.
- **Same pattern elsewhere:** every other caller of `changeVitals` that lowers HP: grep `changeVitals(`/`vitalsOf(` (the finder found this the only one that skips `damageBeast`), plus the master's HP correction (`AdjustCharacterVitals`, `endedByMaster`) which already ends the form.
- **Rules:** RN-02; docs "Wild Shape" section; no temporary HP on the beast pool; overflow goes to the druid. Docs unchanged apart from the traps section.
- **Risk:** the wild-shape events (`wild_shape_ended`, reason `damage`) and the undo of the damage; guard tests: `TestMR037_WildShapeDamageGoesToTheBeast`, `wildshape_log_test.go`, `traps_*_test.go`.

### U4-4: NPC character id in the trap line
- **Root cause:** `firingProto` copies `cc.Character` unconditionally.
- **Where:** `firingProto` (`combat_traps.go:524`): set `CharacterId` only for `v.master` or when the target is a player's character (`cc.Player`); creatures already expose their owner elsewhere. Same alternative-free fix.
- **Same pattern elsewhere:** `firingProto` callers `traps_fire.go:145,208` (master) and `traps_activity.go:246` (out of combat); other event projectors that copy a `character_id` into a player-visible message (grep `CharacterId:` in `combat_log.go`, `highlights.go`, `summary.go`, `live.go`).
- **Rules:** RN-20/RN-29; add the id to the leak tests' deny list (`noLeak`).
- **Risk:** the web app may use `character_id` of a caught PC to highlight it; players keep it. Guard tests: `traps_test.go`, `combat_fog_test.go`.

### U4-6: replayed `SearchForTraps` key
- **Root cause:** a hand-written idempotency branch that skips the actor check every other replay path performs.
- **Where:** `traps.go:183-192`: after the kind check require `done.ActorUserID == m.UserID`, otherwise `invalid_argument` "idempotency_key was already used for another change". Better: reuse the common replay helper if one exists so the check cannot be forgotten.
- **Same pattern elsewhere:** every `GetSessionEventByIdempotencyKey` caller: `traps.go`, `traps_fire.go`, `traps_damage.go`, `scene.go:626`, `creature_cast.go` (`CastSummon` replay does not compare the character or spell: the finder saw it return the first cast's ids for a different spell with the same key; harmless but the same shape), `keySeen` in `combat_theatre.go`.
- **Rules:** docs "Error codes" (`invalid_argument` for key reuse); RN-10 (found trap ids).
- **Risk:** a legitimate retry by the same user must still get the stored answer; guard test: `idempotency_test.go`.

### U4-3: HP spells and Wild Shape
- **Root cause:** `readFxTarget` and `dropToZero` read only the character's own pool.
- **Where:** `combat_spells_hp.go`: when the player's vitals have a Wild Shape, use `wild_shape.hit_points_current/max` for `readFxTarget`; make `dropToZero` call `damageBeast` with the beast's HP (ends the form, no carry-over: confirm the table's reading of "reduces to 0"). Alternative: keep the documented limit and say so in the spell's help text. Since the limit is documented, the cheaper alternative is acceptable for the MVP.
- **Same pattern elsewhere:** `healCombatant` and `damageBeast` already use the beast pool; `isDown`/`isDownIn` use own HP (correct: the druid is not down while the beast stands).
- **Rules:** RN-02, RN-03; update `docs/architecture.md` "Known limits (1)" (~line 1993) if fixed.
- **Risk:** Sleep ordering by HP with mixed pools; guard tests: `combat_spells_hp_test.go`, `wildshape_test.go`.

### U4-12: trap firing on many creatures (same family as U4-1)
- **Root cause:** one audit event carries a per-creature record for every caught creature and the payload CHECK is 4 KiB; the caps (`maxTrapTargets = 40`) were chosen without the size.
- **Where:** `fireInCombat` (`combat_traps.go`) and `FireTrap` (`traps_fire.go:35`). Alternatives: (a) write one event per few caught creatures (`ExtendsID` already exists for "adds creatures to a firing", reuse it); (b) lower the cap to 7 and refuse more with `invalid_argument`. Pick (a): the area of a trap can legitimately hold more, and a move must not be lost. A shared helper that splits any per-creature list into events would also fix U4-1.
- **Same pattern elsewhere:** `joinStart` (U4-1), `trapHook.finish`, `CastSpell` (U4-14), `damage_rolled` events of an area spell.
- **Rules:** a client request within the documented limits must never be `internal`; one idempotency key must still replay the first answer; the undo (`takeBackTrap`) must take back all parts. Update "Traps in play".
- **Risk:** the combat log and undo read `trap_triggered` as one firing; guard tests: `traps_test.go`, `traps_round2_test.go`, `combat_move_test.go`.

### U4-13: creature XP data
- **Root cause:** upstream data error imported as is; no override and no check against the CR table.
- **Where:** `backend/internal/rules/srd51/data/corrections.json` (add xp corrections for the four creatures; the importer applies corrections after copying) or fix `cmd/srdimport/main.go` to derive `xp` from the CR table; then regenerate `monsters.json` and bump the SRD revision/baselines if the repo requires it. Pick the derivation from the CR table with a check in the importer, so a future upstream error cannot slip in (frog and sea horse are CR 0 with 0 XP by convention).
- **Same pattern elsewhere:** any other field copied from upstream without validation (hit points are already checked: all 334 `hit_points_roll` match their averages).
- **Rules:** RN-09; no new dependency; document the correction in the corrections file header.
- **Risk:** saved encounters and tests that pin totals; none pins these four; guard tests: `encounters_test.go`, `rules/encounter` tests.
