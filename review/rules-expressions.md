# Rules review R1: dice expressions and formulas

- **Scope:** `platform/dice` (Parse, Roll, Physical, Min, Max), `rules/dice.go` (ParseDice), `rules/formula`, `rules/effects.go`, every formula and dice string in `srd51/effects/*.json`, the places that read SRD dice (spell damage and scaling, weapon damage, creature hit points and attacks, trap damage, treasure rolls), and the web's dice inputs.
- **Commit reviewed:** `933df75` (`origin/main` of `vfraga/meuRPG`).
- **SRD commit:** `a8abc93b235c158bb8cbf042e54425b9c2fd79b8` (5e-database, 2014/en).
- **Time spent:** about 2 hours of wall-clock time (not measured exactly).
- **Model:** Claude Sonnet 5.5 (`claude-sonnet-5-5`); the six verification subagents also ran on `sonnet`.
- **Status words:** `confirmed` = reproduced by a failing test, no doc names it a decision. `policy` = reproduced by a failing test, the number is wrong against the SRD, and the only thing behind it is a description (`docs/architecture.md:727`, "effects cover levels 1 to 5; above that a feature without an effect appears only as text"), not a decision. `refuted` = a doc names it a decision or the SRD agrees with the app. `unverified` = no input path to drive a test.
- All tests were run with `go test` (or the command in the table). The play and maps integration tests need `MEURPG_TEST_DATABASE_URL='postgresql://root@localhost:26257/defaultdb?sslmode=disable'`.

Belongs to another area (one line each):
- Sheet: no unarmed strike attack is derived (1 + Str, or the Martial Arts die) in `attacks.go`.
- Sheet: Barbarian and Sorcerer Unarmored Defense use mode `max`, so a negative Con or Dex mod never lowers AC as the SRD formula would (arguably a table benefit).
- Spells: Spirit Guardians, Glyph of Warding and Arcane Hand have no structured damage, so the app serves no dice for them; Divine Favor and Branding Smite carry an on-hit damage that is not a cast damage.
- Combat: resistances, vulnerabilities and immunities are not applied (`play/traps_damage.go:28`, documented as not modeled).

## Fix direction

**R1-1 (second damage part, "OR")** Root cause: `link.Spell.Damage` is one `*link.Dice`. Fix in code: carry a list of damage parts through `characters/combatspells.go` and `play/combat_spells.go` (`openSpellPending` once per part, sharing one cast id, so the save and half rule apply to each part). For "4d6 OR 5d6", add handwritten data in `effects/spells.json` (a `damage_choice` kind, bumps the content revision as `CONTRIBUTING.md` says) or parse "AdOR BdN" into a pick of which part grows. Same mistake: `characters/combatspells.go:69-75` heals take one dice too. Docs: `docs/architecture.md` spell cast section, `link.Spell` comment ("one damage type"). Guards: `TestRulesReviewExpressions_IceStormBothDamageTypes`, `TestRulesReviewExpressions_FlameStrikeSlot6`, plus the existing `TestMR014_*` cast tests.

**R1-2 (Eldritch Blast)** Root cause: beams are text in the spell, not data. Fix in code plus handwritten data: a `beams` count by character level on the cantrip (levels 5/11/17), let `RollAttack` for that cantrip allow that many attacks in one action (the Extra Attack counter in `combat_actions.go:757` skips cantrips on purpose), and apply `damage.spell.eldritch-blast` to each. Same mistake: Scorching Ray and Magic Missile already split by count (`combat_spells.go:643`); Eldritch Blast is the only cantrip with beams. Docs: architecture combat-actions section. Guard: `TestRulesReviewExpressions_EldritchBlastBeams`, existing Extra Attack tests.

**R1-3, R1-4, R1-9, R1-10, R1-11, R1-12 (effects above level 5)** Root cause: handwritten effects stop short of the SRD table. Fix in `effects/` data only (bumps the content revision): `fighter.json` add `extra_attack` count 3 on `feature:extra-attack-2` and 4 on `feature:extra-attack-3`, and an `indomitable` resource `1/2/3` (long rest) on the three Indomitable features; `paladin.json` add `modifier` target `save.all`, mode `add`, value `max(1, mod("cha"))` on `feature:aura-of-protection`; `bard.json` give Font of Inspiration a recharge change (needs a small engine change, since a resource's recharge cannot change by level today, or a second resource); `barbarian.json`/`monk.json` Primal Champion/Body and Mind as `modifier` effects on the scores (a cap of 24 needs the score ceiling in `abilities.go` raised for these); `druid.json` Wild Shape max 99 at level 20 as Rage does. Docs: correct the line "cover levels 1 to 5" in `docs/architecture.md:727`. Guards: the seven classes tests, `TestDeriveEachClassAtLevel1`, the level-up sweep and the Pensantus golden (it will not change).

**R1-5 (upcast dice)** Root cause: the 5e-database stores only the base slot for these spells. Fix in data: add the missing per-slot rows through the existing correction layer (`effects/corrections.json` today corrects class table rows and creature multiattack only, so extend it with a spell damage table, or put the rows in handwritten spell effects). Same mistake: none beyond the four spells (a sweep of about 40 spells found no other); Flame Strike is R1-1. Guards: `TestRulesReviewExpressions_UpcastDiceSweep`.

**R1-6 (Dart)** Root cause: the ranged default of `ab := DEX` is applied before the finesse choice. Fix in code: for a finesse weapon always take the better of STR and DEX regardless of range (`attacks.go:36-42`). Same mistake: none found (thrown melee weapons already use STR). Guards: `TestRulesReviewExpressions_DartUsesStrength`, `TestDeriveEachClassAtLevel1`.

**R1-7 (trap 24d10)** Root cause: `maps/spec.go:227` limits a part to 20 dice, below the SRD table. Fix in code: raise the limit to 24 (or to the table's maximum read from `TrapDamageByLevel`); the dice package allows 100. Same mistake: `docs/architecture.md:999` limits a basic sheet attack to 20 dice (a different thing). Docs: the trap spec text in `docs/architecture.md` (trap section). Guards: `TestRulesReviewExpressions_TrapDamage24d10`, `rules/traps_test.go`.

**R1-8 (Cult Fanatic)** Root cause: upstream data error carried through the importer. Fix in data: `effects/corrections.json` `creature_corrections` exists but `content.go:793` (`creatureCorrectionFields`) allows `attacks_per_action` only; add `hit_points` and `hit_points_roll` to that list and correct the creature to 33 / `6d8+6`. Same mistake: none (a scan of every creature finds only this one). Docs: `CONTRIBUTING.md` "Rules content". Guards: both creature tests and `creatures_test.go`.

**R1-13 (division)** Root cause: `expr.AsInt()` truncates. Fix in code: make `/` round down (wrap the result with floor when the quotient is negative) or make the formula check refuse an unrounded division. Same mistake: `formula_test.go:40` documents the truncation. Guards: `TestRulesReviewExpressions_DivisionRoundsDown`, `formula_test.go`, `fuzz_test.go`.

**R1-14 (critical range)** Root cause: no critical threshold anywhere. Fix in code: a `critical_range` value on the derived sheet (19 or 18), passed to `ResolveAttack` (callers at `combat_actions.go:733`, `combat_spells.go:589`, `traps_effect.go:159`), and extra crit dice for Brutal Critical in `CriticalDice`. Docs: architecture combat rolls table.
