# Review, unit 13: the live session outside combat (`review/unit-13-web-live-rest`)

- **Scope:** `web/src/app/pages/live-session/` except `combat/`, plus the shared pieces named in the brief (`fog-map`, `combat-map`, `highlights`, `xp`, `puzzle-boards`, `notes`, `live-toast`, `trap-noticers`, `familiar-eyes`, `wild-shape`, `creatures`, `monsters`, `combatant-token`) and the `core/` state classes those screens use (`SceneState`, `MapState`, `MapReveals`, `PuzzlePlay`, `NoteEditing`, `ExperienceStore`).
- **Commit reviewed:** `ae40f74` (`main` of the fork).
- **Time spent:** about 1 h 30 min (finding in 5 parallel readers, verification in a second wave of one-candidate-per-agent verifiers, then a final serial run of all specs).
- **Models:** the session ran on `claude-sonnet-5-5` (`get_session`: `session_context.model` and `last_served_model` both `claude-sonnet-5-5`). The finder and verification subagents were started with the `sonnet` alias; the harness does not report their served model ID.
- **Method note:** every confirmed row has a Vitest spec, `review13-u13-NN.spec.ts`, next to the code. Each spec has a passing control test (proves the setup) and a failing test that asserts the correct behaviour. Final evidence run, all specs in one build:
  `cd web && npx ng test --watch=false --include 'app/**/review13-*.spec.ts'` gave 31 files, 73 tests, 42 failing (the defect assertions) and 31 passing (the controls). U13-30 was re-run on its own after a fix to the spec (`--include 'app/pages/live-session/review13-u13-30.spec.ts'`: 1 passed, 1 failed).
  Each spec is run alone with `cd web && npx ng test --watch=false --include 'app/<folder of the spec>/review13-u13-NN.spec.ts'`.
- **Result in one line:** no RN-10 leak reaches a player from this unit: the finders traced every player-side component (scene, puzzle, trap, treasure, shown image, map pins) and found no rendering of a hidden field the server sent, no `innerHTML` / `bypassSecurityTrust*`, no Web Storage. The defects are client races, double submits, stale panels and wrong targets.

No spec changes production code. No finding is critical; none is rated high.

## Fix direction (confirmed findings)

Common rules for every web fix below: no new dependency; no Web Storage; keep idempotency keys per intent (`ActionKey.keyFor`, `core/connect/idempotency.ts`) and reuse them on a retry; errors become text through the existing `*-errors.ts` mappers, never `err.message`; master-only UI stays behind `isMaster()`; none of these changes touch the server contract unless said.

**Family 1: stale in-flight reads and answers (U13-02, 03, 25, 26, 16, 29, 30, 10).** *Root cause:* each state class guards by a single `generation` counter that local writes bump (dropping reads), or by none (reads overwrite local writes); answers are applied by arrival order into a `MapState` / `SceneState` that outlives the map or puzzle they were for. *Fix:* `core/maps/map-state.ts`: make `upsertPoint` / `upsertToken` ignore a point whose `mapId` differs from `map()?.id` (fixes every caller of U13-25 and U13-16 at once; alternative: guard in each caller, more code and easy to miss); bump `generation` in `moveToken` / `upsertToken` / `upsertPoint` / `removePoint` / `removeToken` / `setMap` so an older read is dropped (U13-26), and re-run one `refresh()` when a read is dropped. `core/play/scene-state.ts`: when a local answer drops a pending read, schedule one more `refresh()` instead of losing it (U13-02, same in `core/notes/notes-state.ts:109-174`); in `stage-controller.ts` serialise stage writes through one queue or sequence-tag the answers and `refresh()` after the last one settles (U13-03). `live-session.ts`: a per-call sequence for `reloadLeftImages` (also `reloadMaps` ~920-926 and `loadCombat` ~705-710, same shape), and an "event seen since the read began" marker so `readSnapshot` skips `shownImage` / `shownKeep` / `currentMapId` when an event already applied (U13-29, U13-30). `puzzle-play.ts` `refresh()`: compare `id` with `pendingId` after the await and in the catch (U13-10; `send()` catch ~257-263 and `tryHint()` ~287-295 set a stale `message` the same way). *Same pattern elsewhere:* `upsertToken` callers `session-map.ts:240,250`, `pages/maps/map-editor/map-editor.ts:431,597,607,710`, `light-panel.ts:75`, `fog-player-tools.ts:92`, `map-reveals.ts:64`;
