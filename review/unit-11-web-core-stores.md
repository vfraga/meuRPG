## Fix direction

Common root of most rows: **an async answer is applied without checking that the thing it was asked for is still the current one.** The repository already has the idiom (`seq`/`generation` counters, `ActionKey`); the fixes below extend it. None changes a server contract. Project rules that apply to all: no new dependency; error text through the existing `*-errors.ts` mappers (`docs/architecture.md` "Error codes"); keep stale-answer tests next to the code; no Web Storage.

**U11-23 (and U11-21, U11-22).** Root: `PuzzlePlay.open()` does not invalidate work that belongs to the previous puzzle. Fix in `puzzle-play.ts`: capture `const id = this.pendingId` when a tap/hint/refresh starts and drop the effect (`gone`, `hintTry`, `message`, queued `send`) when `id !== this.pendingId`; make `open()` reset `bellQueue`, `bellEpoch`, `pending`, `hintBusy`, `message`, `hintTry`, `gone`. Same pattern: `send` catch `:258-263` (sets `message` and calls `refresh()` unchecked), `finally :266` (`pending--`), `refresh :146`, `watchReveal :194` (in-flight refresh not covered by `stopReveal`). Alternative for the queue: carry `puzzleId` in each queued tap and skip it at run time (smaller change, keeps `open()` simple); pick the id check, since it also covers hints. Risk: `puzzle-play.spec.ts` bell/hint tests; a mid-sequence reset must not eat the first tap of the new puzzle.

**U11-01.** Root: `clear()` mutates `batches` under a running `drain()`. Fix in `paint-queue.ts`: bump a `generation` in `clear()`; `drain()` captures it with the batch and, when it changed, neither `shift()` nor writes `batches[0]` back (or compare `this.batches[0] === batch`). Same shape: `paint-queue.ts:163` and `:174`. Keep `PaintSession.open`'s busy branch (`paint-session.ts:68-76`). Risk: `paint-queue.spec.ts`, `paint-session` tests; a refused batch must still stay for retry.

**U11-11 (RN-10 flavour).** Root: the card read and the list refresh race over one cache that only the list invalidates. Fix: in `Spells.contentChanged` run `await state.refresh()` first and then `loadCard(selected, true)`, with `loadCard(…, force)` bypassing/clearing `detailsByKey`; or have `SpellsClient.noteVersion` be fed by the hint itself (clear caches when the hint arrives). Pick the second: the hint is the authoritative signal and other screens benefit. Same pattern: any `ContentWatcher.whileLive` user that reads through a cached client in parallel with a list (`pages/content/*`, `core/content` table clients: grep `whileLive`). Also covers a spell switched off: the card must show the "gone" state (`not_found`). Docs: "Live table content". Risk: `spells.spec.ts`, `spells-client` cache tests.

**U11-24.** Root: caching promises, not values. Fix in `solve-targets.ts:75,83,130`: `.catch(e => { cache.delete(key); throw e; })` on every cached promise, and clear all caches in `use()` when the id changes. Risk: `solve-targets.spec.ts`; none otherwise. Same pattern: `SpellsClient` detail maps and `LevelUpClient` `~134-148` (rejected promises cached; evict on failure), `LightPresets`/`SceneChecks` caches (never invalidated; intentional unless table content changes).

**U11-08, U11-06 (campaign switch on a reused component).** Root: a page-level store/handler is reused across `paramMap` emissions without a reset or sequence. Fix: in `CampaignDetail.load()` take a ticket (`const mine = ++this.loadSeq`) and ignore `loaded.then` when it moved (or use `switchMap` over `paramMap`); in `ExperienceStore.load()` when `campaignId` changes reset `rows`, `awards`, `nextPageToken`, `xpMode`, the seqs, and make the catch set `'error'` whenever the state is still `'loading'`, not only when the lists are empty (same logic at `refresh()/loadTreasures() ~118-119`). Alternative for U11-06: destroy the store by gating it behind the page's `status` like `MilestonesStore` already is; the reset is cheaper and protects the store itself. Same pattern: every page with `paramMap` + async load and no guard (gallery `:132`, bestiary, treasure, spells, encounters pages; low reachability today, see U11-25), `MilestonesStore` (latent: `load` keeps `list`, `adopt` takes no id). Risk: `campaign-detail.spec.ts`, `experience-store.spec.ts`.

**U11-15.** Root: lenient parser with a valid zero. Fix in `effect-draft.ts:325-328`: return `undefined`/NaN on unreadable text and add a draft validation message (as the editor does for other fields) that blocks save; accept an optional trailing `m` if desired. Same call sites: `spell-draft.ts:360,385,460,504`, `effect-picker.ts:184`. Docs: none. Risk: draft specs that feed odd text expecting 0.

**U11-21 → see U11-23. U11-12/U11-13.** Root: `refresh()` neither takes a ticket nor bumps `seq`. Fix in `spells-state.ts`: `const mine = ++this.seq` in `refresh()`, check `mine !== this.seq` before writing, and compare the token in `more()`. Risk: `spells-state.spec.ts` (search vs refresh ordering).

**U11-20.** Root: list answers are not reconciled with per-id writes. Fix in `puzzle-session.ts read()`: skip ids whose `applied` ticket is newer than the one captured when the list started (or have `replace()/changed()` bump `listSeq`; pick the first, it keeps unrelated runs fresh). Risk: `puzzle-session.spec.ts`.

**U11-03, U11-04.** Root: local mutators and in-flight reads share state with no ordering. Fix in `map-state.ts`: bump `generation` in `upsertPoint/upsertToken/moveToken/removePoint/removeToken/setMap` (then refetch if the mutation was not authoritative); in `map-reveals.ts` capture the map id and drop the `upsert` when `stateOf().mapId() !== mapId`. Same pattern: `pages/maps/map-editor/map-editor.ts:~462-475` (`createPoint` upserts after the await), `pages/live-session/traps/trap-panel/trap-panel.ts:145,222`, `core/maps/fog-view.ts:84` (check). Risk: `map-state.spec.ts`, `map-reveals.spec.ts`, drag-save tests (`move-saves`).

**U11-17, U11-19.** Root: `generation` serves two purposes (invalidate reads on campaign change, and on own write). Fix in `notes-state.ts`: bump `generation` only in `clear()`; writes patch their own note and leave reads alone, and capture the campaign/generation in the write closures, dropping their effects after `clear()`. Also guard `refreshScenes :89-95` the same way. Risk: `notes-state.spec.ts` (list/write ordering).

**U11-16.** Root: Save not gated on `dirty`. Fix in `note-editing.ts save()`: when editing and nothing changed, close the form and return without an RPC; also disable the button on `!dirty` in `notes-sheet.html:67`/`notes-panel.html:24`. `notes-errors.ts` maps every InvalidArgument to one text; keep. Same shape: `notes-state.update :161`/`NotesClient.update :47` send empty changes. Risk: `note-editing.spec.ts`.

**U11-14.** Root: `refresh` re-reads data but not the lookups built from it. Fix in `content-entry.ts refresh()`: call `loadExtras` (or rebuild `catalogVm`) with a sequence guard, as `content-list` already does. Risk: `content-entry.spec.ts`.

**U11-18.** Root: `confirmSwap` lacks the `version` guard `generate()` has. Fix: `const mine = this.version` before the await, skip the three `set`s when it moved (also guard the `startSwap` catch `:214-217`); optionally disable band/type controls while `swapBusy()`. Risk: `generate-sheet.spec.ts`.

**U11-10.** Root: two code paths re-trim skills without re-deriving expertise/prepared. Fix in `levelup-draft.ts`: after `trim(skills)` in `setSubclass`/`adopt`, filter `expertise` against the trained set and `prepared` against the book (reuse the `toggleSkill`/`toggleSpell` filters). Risk: `levelup-draft.spec.ts`.

**U11-26.** Root: `fold()` copies the server rule loosely. Fix in `puzzle-text.ts:56-58`: `\p{L}\p{Nd}` and a per-code-point simple lowercase matching Go's `unicode.ToLower` (no final-sigma/locale special cases). Test against the Go output (this spec has the table). Docs: "Puzzles (MR-038)" if it mentions folding. Risk: `puzzle-text.spec.ts` accents (`Ação`) must still fold the same.
