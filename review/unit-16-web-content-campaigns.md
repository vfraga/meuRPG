# Review unit 16: campaigns, table content and the tools pages (web)

- **Scope:** `web/src/app/pages/{content,campaign-detail,campaign-document,table-rules,bestiary,spells,encounters,treasure,puzzles,campaigns,profile,invite,invite-error,home,credits,server-unavailable,not-found}` and the remaining `web/src/app/shared/*` pieces listed for the unit (markdown, treasure-facts, portrait, person-pick, hidden-switch, count-stepper, check-box, segmented, table-mark, pair-foot, dice-choice, session-link, session-time, live-pill, chest-icon, fiction-notice).
- **Commit reviewed:** `ae40f74b648bf653560d54e7ab1b3128a5370f8c` (`main` of the fork).
- **Time spent:** about 8 hours wall clock, most of it waiting on concurrent Angular builds.
- **Model:** the main session ran on `claude-sonnet-5-5`. The finder subagents used `opus`; every verification subagent used `sonnet`.
- **Method:** five finder agents read the slices end to end; every candidate that was tested went to a fresh verifier that only got the claim. No production code was changed. Each confirmed finding has a failing Vitest spec `web/src/app/**/review16-u16-NN.spec.ts`.

Answers to the unit's questions, with evidence:

- **Markdown:** no live HTML, no `javascript:` link, no foreign image. `parseMarkdown` builds a token tree, the template only uses interpolation and property bindings, links are https-only through `new URL` without userinfo, images are only `/images/<uuid>`. No `innerHTML` or `bypassSecurityTrust*` anywhere in the unit. Its only defect is performance (U16-07).
- **Off-site or cross-campaign navigation:** none found. The invite link is built from `window.location.origin`, `return_to` must start with `/`, route ids are only sent as `campaignId` and the server decides access. A stale-answer race when the route parameter changes exists on `campaign-detail`, `campaign-document` and `table-rules` but no in-app link moves between two campaigns, so it is listed as unverified.
- **Pending or removed members:** pending members get no master screen (`awaitingApproval` is treated as not found or forbidden everywhere checked). A removed member keeps a stale view but every call fails server-side.
- **Content editor over a newer revision:** content entries and the campaign document send `expected_revision` and handle the stale answer. Table rules and `UpdatePuzzle` have no revision (server-side, unverified).
- **Web Storage:** none.
- **Raw server error or internal id on screen:** only Home (U16-08). Internal keys can show in content lists in a failure path (unverified, see below).

## Fix directions

Run any spec with: `cd web && npx ng test --watch=false --include 'src/app/<path>/review16-u16-NN.spec.ts'`. Note for whoever runs them together: the Angular builder compiles every spec, and several concurrent builds exhaust the 512 MiB class of machines.

**U16-01 and U16-02 (close while busy, key per dialog).**
- Root cause: the sheet frame's `(closed)` is not tied to `busy()` and the idempotency key belongs to the component instance, so the user can lose the answer and the retry looks like a new intent.
- Fix in `place-sheet`, `create-npc-sheet` (and the sheets listed below): bind the frame's close to a guard (`if (busy()) return;`) and open the sheet with `disableClose` while busy, or keep the key in the opener (page) so a reopen reuses it until a success or an edit. Pick the guard (smaller; same approach as the "Parar de esperar a imagem?" confirm in `shared/image-generate`); the key-in-opener is only needed if closing mid-flight must stay allowed.
- Same pattern: `shared/monsters/put-sheet/put-sheet.html:7,134`, `shared/wild-shape/wild-shape-sheet.html:8,56`, `pages/encounters/save-sheet/save-sheet.html:7,105` (replace in place, so only a lost confirmation), `pages/character-sheet/creatures-panel/summon-sheet.html:8,168`, `shared/familiar-eyes/familiar-eyes-sheet.html:1,24`; per-instance `newKey()` in `trap-search-sheet.ts:156`, `trap-fire-sheet.ts:120`, `start-combat-dialog.ts:126`, `feature-sheet.ts:118`, `scene-roll-sheet.ts:82` (each needs a check that its close is guarded).
- Rules: `docs/architecture.md` "Web app" sheet conventions; no new dependency. Risk: users can no longer dismiss a stuck request, so keep the busy window bounded by the RPC deadline. Guards: `place-sheet.spec.ts:235`, `create-npc-sheet.spec.ts:235`.

**U16-03 (bulk switch on an unloaded filter).**
- Root cause: `narrowed()` is derived from the filter value, `rows()` from the loaded list, so they disagree while the list loads.
- Fix in `options.ts`: define `narrowed()` as "filter set and `classSpells` has the entry", and disable "Ligar/Desligar todas" (`turnOnDisabled`/`turnOffDisabled`) while the class list is pending; on a failed list call show a message instead of silently resetting the filter. Alternative: compute the target set in `setAll` from the same signal that renders the count; same effect, more coupling.
- Same pattern: none found (the level filter is synchronous). A single page of 400 can truncate a class list once table spells are added: page through `next_page_token`.
- Risk: the options specs (`options.spec.ts:249` resolves immediately). 

**U16-04 (player keeps stale body).**
- Root cause: `refresh()` applies the draft-protection rule regardless of whether anything is being edited.
- Fix in `content-entry.ts:309`: keep `open` only while `editing()` (the editor is mounted and dirty), otherwise adopt the new entry; keep the stale-save refusal path as is. Same pattern: none (`revision !==` appears once).
- Rules: RN-23 (off content must disappear from players). Guards: `content-entry.spec.ts:377,392` (master editing).

**U16-05 (stale spell card).**
- Root cause: `details()` is served from a cache that `noteVersion` clears only after the list answer, but the page reloads the card in the same tick.
- Fix: in `Spells.contentChanged`, await `state.refresh()` before `loadCard(selected, true)`, or make `loadCard(…, true)` bypass the cache. Prefer awaiting the refresh (one place, no cache API change).
- Same pattern (not verified, each a Promise cache keyed by content): `core/combat/spell-catalog.ts:17` (most likely), `core/levelup/levelup-client.ts:58`, `core/creatures/creatures-client.ts:69`, `core/maps/scene-actions.ts:83`, `core/maps/light-presets.ts:49`, `core/traps/trap-presets.ts:18`.
- Guards: `spells.spec.ts:461` uses a cacheless fake; add the real client to any new test.

**U16-06 (Unauthenticated).**
- Root cause: the client never reacts to a dead session after the startup `GetMe`, and the shared error mapper treats it as a transport error.
- Fix: in `describeConnectError` add `Code.Unauthenticated` with "Sua sessão terminou. Entre de novo." and, better, a Connect interceptor in `core/connect/transport.ts` that calls `AuthService.refresh()` on `Unauthenticated` so the guard and app bar move to signed-out. Pick the interceptor (fixes all 64 call sites); do the message too as the fallback.
- Same pattern: all `describeConnectError(` callers (64); `content-client.ts:157`, `document-copy.ts:29` and `imagegen-errors.ts:103` already handle it. Note `document-copy.ts:29` promises "o texto continua aqui" but sign-in is a full page load that skips `canDeactivate`: re-word or offer to copy first.
- Rules: `docs/architecture.md` ~306-314 (`signed-out` comes only from `GetMe`); update it. Risk: a refresh loop if `GetMe` itself returns `Unauthenticated`; do not refresh on `GetMe`.

**U16-07 (quadratic list continuation).**
- Root cause: immutable array copy per continuation line inside the loop.
- Fix in `markdown.ts:131`: push into a mutable inline array per item and freeze at `flushList`, or concatenate the continuation text and parse once per item. Also count the work in `budget`.
- Same pattern: no other `x = [...x, ...]` in the app (grep). Guards: `markdown.spec.ts`; keep the parse output identical.

**U16-08, U16-09, U16-11 (small page fixes).**
- U16-08: use `describeConnectError` in `home.ts:75`; change `home.spec.ts:58-69`.
- U16-09: wrap `decodeURIComponent` in try/catch and treat a failure as no token, strip the fragment first. Guard: the existing "strips with replaceState" spec.
- U16-11: keep the token in memory and show a "Tentar de novo" button for transient errors (calling `accept()` again); also in the `unavailable` branch (`invite-accept.ts:79-83`).

**U16-15 (revoke wipes the list).** Root cause: an action failure reuses the list-load state. Fix in `invites.ts:175`: keep `listState` as `ready` and put the failure in a separate `actionError` signal rendered above the list (as `pending-members.ts:62,95` and `reached-milestones.ts:113` do). Also disable the row's button while its call runs. Same pattern: none found in the directory; `createInvite` at `invites.ts:109,143` should be checked for the same reuse.

**U16-16 (stale chip index).** Root cause: the identity of a chip is its position in a server view that lags the draft. Fix: remove by `characterId` (`draft.removeNpc(id)`), or disable the ✕ while a measure is pending. Pick the id (also correct after a failed measure). Same pattern: none with the stale-view shape; other index removals take the index from the state they mutate (`character-editor.ts:822,837`, `riddle-form.ts:116`, `parts-field.ts:193`, `hints-field.ts:83`, `table-rules.ts:458`). Guard: `encounter-builder.spec.ts:250`.

**U16-17 (session card never updates).** Root cause: the card is the only place that announces a session on its own page but loads once. Fix in `game-session-card.ts`: derive "session open" from `OpenSessions.sessions` (already polled) for players, keeping the `getCurrentSession` call for the details; or re-load when `sessions` changes. Same pattern: none found. Docs: `docs/pt-BR/produto/historias.md:205` and RN-06 describe the notice; state that the card is the page's announcement. Guards: `game-session-card.spec.ts:226,235`, the live-notice specs.

**U16-10 (rules saved over a newer edit).**
- Root cause: the response replaces the whole draft. Fix: after the await set only `saved` and recompute `changes()` against the sent draft; keep `draft` as is. Alternative: disable controls while saving (simpler, a visible lock). Pick the first. Server side (unverified): `SetTableRulesRequest` has no revision, so two tabs overwrite silently (`proto/meurpg/campaigns/v1/campaigns.proto:712`).

**U16-12 (puzzle preview stuck).** Root cause: `lastKey` not reset when the kind has no start preview. Fix in `puzzle-form.ts:~250`: when `previewKey === ''` set `lastKey = ''` (as `cipher-form.ts:165-180` does). Pillars share the path.

**U16-13 (sub-race select).** Key the select on `isNew()` like `subclass-editor.html:15`, not on `raceKey !== ''`.

**U16-14 (unarchive refusal).** Handle `InvalidArgument` in `contentErrorText` by consulting `refusalOf()` (`content-client.ts:121`) and show the violations as the save path does; also `content-list.ts:275`, `options.ts:227`, `players-switch.ts:113` (not checked).
