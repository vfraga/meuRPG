## Fix directions

### U8-1 choice count

- Root cause: `checkEffect` validates only `count >= 1` for a `choice`; nothing relates the count to what can be chosen.
- Where: `rules.checkEffect` (`overlay_features.go`), `case "choice"`. For `feature`, require `count <= len(from)` (and a sane `count` of at most 20, like `maxEffectList`); for `skill` / `expertise` / `cantrip` / `language` / `tool` give a fixed maximum (for example 18 skills). Report `ReasonValue` at `.count`. The alternative is to clamp in `featureGains`, but that hides the master's mistake; refuse at write time (pick this).
- Same pattern elsewhere: `levelup.go:522-533` (`g.skills += e.Count`, `g.expertise`, `g.cantrips`), `choices.go:104-109` (`allowed += a.effect.Count`), `spellcasting.go:168` (`extraCantrips += e.Count`), `tablemenu.go:160` (the menu's `count` field has `Min: 1` and no `Max`), `overlay_class.go:202` (`SkillChoose <= len(SkillFrom)` is checked, but `MulticlassSkillChoose` only against `SkillFrom` too, fine), `range_ft` of `sense` (`tablemenu.go:136`, no `Max`).
- Rules to respect: error codes in `docs/architecture.md` ("Errors"), validation happens in the first pass or in `compileEffectsOf`, no new dependency. Docs that change: "Closed menu" row and `docs/product/stories.md` MR-025 if it lists limits; the web editor's count field limits (`web/src/app/.../table-class` editors) should read the new `Max` from `EffectMenu`.
- Risk: existing stored content with a too-large count would stop loading (`TableSource` returns an error and the campaign cannot be read). Run the check only for `Strict` entries and clamp (or ignore) in stored ones, as `stripUnused` already does. Guarded by `TestWithRefusals`, `TestLevelUpSweepTable`.

### U8-2 hit point maximum

- Root cause: `Derive` applies `hp.max` modifiers with no floor and `With` does not constrain them.
- Where: `rules.(*deriver).hitPoints` (`hitpoints.go:52`): `x.d.HitPointsMax = max(x.modifiers("hp.max", hp), TotalLevel)` (the SRD floor is 1 per level) and optionally an `Issue` when the floor was applied. Alternative: refuse in `checkEffect` any `hp.max` modifier whose formula is not provably positive; hard with formulas, so floor in `Derive` (pick this).
- Same pattern elsewhere: `armor.go:82` (`ac` can be negative), `abilities.go:329` (initiative, legitimate), `attacks.go:49,56,86` (damage and attack bonuses), `spellcasting.go:70` (already floored at 0; a custom `prepared_max` can be 0, the default is `max(1, ...)`), `characters/derived.go:53` sends the raw value.
- Rules: `Derive` never fails and reports an `Issue` instead ("the app is an assistant"); golden `testdata/golden/table-character.json` must not change; `characters/vitals.go:80` already clamps.
- Risk: a deliberate "cursed" table effect loses its effect below the floor. Guarded by `TestDeriveTableCharacterGolden` and the vitals tests.

### U8-3 spell dice

- Root cause: `plainDice` validates the count only; `ParseDice` accepts any `faces >= 1`.
- Where: `rules.plainDice` (`overlay_spell.go:19`): require `f.Sides` in the table dice. Pick the set from `platform/dice.validSides` (4, 6, 8, 10, 12, 20, 100) or tighten to d4..d12 as the SRD spells use; `rules` must not import `platform`, so duplicate the list with a test that compares it to `dice.Parse`. Alternative: raise the clamp in `play/combat_reactions.go` and have `Parse` accept any die; that spreads the problem into the database columns and the physical-dice UI, so refuse in `With` (pick this).
- Same pattern elsewhere: `rules/spelleffects.go:137-138` (`ParseDice` for hit point pools), `rules/traps.go:285,298` (trap damage), `maps/spec.go:221` (`rules.ParseDice` on a map spec; check what follows), `play/combat_actions.go:1727` (heal events hardcode 1d10; unread). The SRD-sourced ones are safe; the map spec path should be checked by the unit that owns `maps`.
- Rules: RN-18 physical dice; error `ReasonValue` at `.dice`, `.per_slot_level`, `.per_tier`, `.heal.dice`; docs: "Spell" row of the architecture table.
- Risk: stored table spells with other dice stop loading; apply the check on `Strict` entries only. Guarded by `TestSpellDetailsOfTableSpells`, `TestWithRefusals`.

### U8-4 formula overflow

- Root cause: only literals and the final result are bounded; intermediate int arithmetic wraps.
- Where: `formula.Compile` / `Program.Int`. Simplest: evaluate with float64 semantics or compile `*` into a checked multiply (Expr's `expr.Operator("*", ...)` with an overflow-checking function), or reject in `check` any product whose static bound exceeds `MaxResult` (multiply the literal magnitudes while walking the tree; a function call counts as the maximum it can return). Pick the static bound: it fails at write time, with no runtime cost.
- Same pattern: only this package does int arithmetic on master input. Also check `math.IsNaN/IsInf` before the float to int conversion in `Int` (U8-9).
- Rules: `FuzzCompileFormula` must keep passing; keep the error messages free of Go types; update the "Limits" bullet in "Formulas in Expr, sandboxed".
- Risk: rejecting formulas that legitimately multiply (`5 * classLevel("paladin")`, 100 at most); the SRD effects load at server start, so run `LoadSRD` tests.

### U8-5 and U8-6 error codes and name characters

- Root cause: classification by English message text (`reasonOf`, `attrOf`, `effectError`), and `unicode.IsControl` alone for "one line".
- Where: raise the entry-level errors with an explicit reason, as the reserved-key check already does (`ovErr(...).reason(ReasonName)` in `checkEntryName`, `.reason(ReasonText)` in `checkText`); keep the keyword table only as a fallback. For names, reject `unicode.IsControl`, `unicode.Is(unicode.Zl|Zp|Cf)` and `unicode.Bidi_Control`; `platform/names` already has a precedent for `Bidi_Control`.
- Same pattern: `unicode.IsControl` only at `rules/overlay_spell.go:284` (reaction trigger) and `rules/spelltarget.go:109`; `checkText` / `checkTextAt` refuse no control characters at all (NUL accepted); `platform/idem/idem.go:42`, `maps/imagegen.go:959,971`. Keyword classification: `overlay_error.go:103` (`attrOf`) and `overlay_features.go:287` (`effectError`). The web copy says names run 1 to 60 letters while the engine allows 80 (`content-violations.ts`).
- Rules: reason codes are stable (`docs/architecture.md` "Errors"), web mapping changes with them; no new dependency.
- Risk: stored names with such characters would stop loading: validate on `Strict` entries only. Guarded by `TestOverlayErrorFields`, `TestWithRefusals`, the tests in `overlay_paths_test.go`.
