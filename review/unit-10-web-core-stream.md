## Fix directions

### U10-2 (snapshot overwrites newer stream events)
- **Root cause:** the snapshot is applied as the truth, with no rule for events that arrived after it was requested; only vitals carry a revision.
- **Where:** `LiveSession.readSnapshot` / `openStream` handlers. Approach A (pick): keep a monotonic `streamTick` counter bumped by `onCurrentMap` and `onShownImage` (and `showMap`/`shownImageChanged`); `readSnapshot` records it before the request and skips `currentMapId`/`shownImage`/`shownImageKeep`/`mapState.open` for any field whose event arrived since. Approach B: the server adds a revision to `GetLiveSessionResponse` for map and image and the client compares (cleaner, needs proto and backend change).
- **Same pattern elsewhere:** `loadCombat` (`live-session.ts:~700`) applies a read with only the revision guard; `scene.refresh`, `puzzles.refresh`, `notes.refresh` already have counters. `combatStarted` and `changeDice` set state from answers with no guard.
- **Rules:** RN-10 (a withdrawn image must not reappear); docs "Live session" paragraph on the gap must describe the new rule.
- **Risk:** skipping the snapshot's map could leave the page on the wrong map if the event itself was lost; guarded by `live-session.spec.ts` map cases. Add the U10-2 spec to the suite.

### U10-1 and U10-3 (ended login session is invisible)
- **Root cause:** no central place reacts to `unauthenticated`; `AuthService.state` is read once.
- **Where:** `core/connect/transport.ts` (an interceptor next to `rateLimitInterceptor`): on `Code.Unauthenticated` from any unary call except `GetMe`/`SignOut`, call `AuthService.refresh()` once (debounced); `refresh()` then settles to `signed-out`, `OpenSessions` stops by its existing effect, and the user menu shows "Entrar". Pair it with `describeConnectError` returning "Sua sessão acabou. Entre de novo." for `Unauthenticated` (as `imagegen-errors.ts:103` already does) and, for pages, a call to `signIn(router.url)`. The interceptor needs `AuthService` lazily (`inject(Injector)`) to avoid a cycle, since `AuthService` injects the transport.
- **Same pattern elsewhere:** `open-sessions.ts:159`, `live-session.ts` unary handlers that `catch {}` (`loadCombat`, `reloadMaps`, `reloadLeftImages`, `refreshCampaign`), `document-copy.ts:29`, `content-client.ts:157`, `adjust-vitals.ts:181` (uses `location.pathname`, which drops the query), and the ~43 `describeConnectError` callers without an entry.
- **Rules:** `docs/architecture.md` "Session state and the sign-in/sign-out flow" (state table) and the error codes table; sign-in stays a full-page navigation; no Web Storage.
- **Risk:** a redirect loop if `refresh()` itself answers `unauthenticated` and sign-in returns unauthenticated; do it once per page load. Existing `auth.service`, `auth.guard`, `open-sessions` and `user-menu` specs guard the states.

### U10-6 (vision and creatures not re-read after reconnection)
- **Root cause:** `ready` re-reads data through `readSnapshot`, but the fog view and the creatures tick are driven only by events.
- **Where:** `readSnapshot` (after `mapState.open`): call `this.scheduleVision()` and `this.creaturesTick.update(n => n + 1)`.
- **Same pattern elsewhere:** `visionTick`-driven children (`session-map`, `fog-master-panel`, `fog-player-tools`) and the master's "Ver como" read; `onContentChanged` is not handled by the page at all (`live-session.ts` handlers; the stream type exposes it) — a catalog change during an outage is also lost.
- **Rules:** RN-10 (what a player sees must follow the server's current vision); comment at `live-session.ts:~668` must stay true.
- **Risk:** one extra vision read per reconnection; covered by the fog cases of `live-session.spec.ts`.

### U10-4 (no-session reload loop)
- **Root cause:** an effect that reloads on a condition its own reload leaves true.
- **Where:** the effect at `live-session.ts:474`; remember the `liveCampaignIds` snapshot it already acted on (reload only when the id newly appears: previous set lacked it), or require `phase` to have come from a poll refresh. Alternatively add a backoff in `load()` for the `no-session` path.
- **Same pattern elsewhere:** `LiveStream.restart()` loops with backoff (fine); `readSnapshot` default branch restarts forever on `forbidden`/`invalid` codes (no cap) at `live-session.ts:~700`.
- **Rules:** RN-06 (the notice is a light poll; do not add a second connection); abuse limits in `docs/architecture.md`.
- **Risk:** the page must still open by itself when the master starts a session; `live-session.spec.ts` "opens the session by itself when the master starts it" guards that.

### U10-5 (in-flight map read overwrites a token move)
- **Root cause:** `moveToken` (and `upsertToken`, `removeToken`, `upsertPoint`, `removePoint`, `setMap`) mutate state without bumping `generation`.
- **Where:** `core/maps/map-state.ts`: `this.generation++` in each in-place mutator, as `SceneState` does. Cost: a read in flight is dropped, so follow with a refresh when the in-place edit came from the stream, or accept the next event heals it.
- **Same pattern elsewhere:** `CombatState.applyTurn/applyMove` (`core/combat/combat-state.ts`) have the same shape, relieved only by the revision guard and the following `encounter_changed`.
- **Rules:** none beyond the stale-answer rule stated in the class comment.
- **Risk:** dropping a read that carried newer unrelated data; `map-state.spec.ts` guards the overlap rules.
