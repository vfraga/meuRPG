## Fix direction

### U3-1 (a down player moves)
- **Root cause:** `MoveCombatant`'s player branch re-implements "may act now" by hand (status, `actsNow`, `placed`) instead of using the gate every other write uses.
- **Where:** `combat_move.go` `MoveCombatant` and `GetMoveOptions`: after the `!v.master` checks call `s.gate(ctx, c.tx, ...)` (or `isDown`/`Defeated`) and return `gateError(code)`; `GetMoveOptions` uses the pool form (`tx == nil`).
- **Same pattern elsewhere:** grep the callers of `actsNow` in `combat_*.go` that do not also call `gate`: `combat_move.go` (both), `SpendMovement` and the theatre movement in `combat_theatre.go` (not audited), `combat_death.go` roll gate. `GetMoveOptions` for a down character (`combat_move.go:655-662`).
- **Rules to respect:** one connection inside `db.InTx` (use `c.tx`); error code `failed_precondition` with `EncounterBlocked` `COMBATANT_DOWN`; the master stays unrestricted ("master has the last word"). Docs: RN-21 text and "Movement in combat" should say a down character cannot move.
- **Risk:** a down player who must be moved by the master (stabilising adjacent) still can via the master path; `TestRN21_*` and `combat_move_test.go` guard the normal walk.
- **Sketch:** `if !v.master { if code, err := s.gate(ctx, c.tx, m.CampaignID, c.enc, target); err != nil || code != UNSPECIFIED { return nil, ... } }`.

### U3-2 (dead character breaks NPC moves)
- **Root cause:** a combatant's character can leave `status='active'` (dead, via the characters RPC) without the combat knowing, and `isDown` treats the resulting `not_found` as a fatal error.
- **Where:** two options. (A) `isDown`: treat `not_found` as "out of the fight" (down/true), as `EndTurn` already does (`combat.go:838`). (B) give `MarkCharacterDead` a hook into play that sets `defeated` and runs `leaveTurn`. I would do A now (one function, covers all callers) and B later.
- **Same pattern elsewhere:** `isDown` callers `combat_opportunity.go:118`, `:281`, `combat_actions.go:77`, `:494`, `:1690`, `combat_theatre.go:372`, `combat_reactions.go:53`; bare `GetVitalsTx` calls without a `not_found` guard: `combat_actions.go:1110`, `:1256`, `combat_vitals.go:64`, `:104`, `combat_spells_hp.go:47`, `combat_undo.go:287`, `wildshape.go:123/173/390/399`, `familiarsight.go:180/318/389`, `creature_cast.go:215`, `combat_death.go:120`.
- **Rules to respect:** reads go through the transaction (`tx`); no new dependency; error codes unchanged (a `not_found` for a character the caller asked about directly stays).
- **Risk:** treating missing as down makes a dead PC skipped as reactor/target; `TestMR013_*` and `combat_opportunity_test.go` guard offers.

### U3-3 (defeated/dead member keeps acting)
- **Root cause:** "leaves the turn" is implemented only for removal (`leaveTurn` + delete); defeat and death change `defeated` but not `turn_state`, and `EndTurn`/`leaveTurn`/orphan check count acting by `TurnState` alone.
- **Where:** simplest and most robust: exclude `Defeated` where acting is computed (`combat.go:794`, `:875-881`, `combat_turn.go:160-164`, `combat_view.go` `turnFor`'s `acting`, `actsNow`), and also set `turn_state='idle'` in the defeat paths (`SetCombatantHitPoints` when it defeats, `SetCombatantDeathSaves(defeated=true)`), mirroring `SetCreatureCombatantsDismissed` (`queries.sql:621`). Alternative: call `leaveTurn` from every defeat path (more places to forget). I would pick the SQL + `Defeated` filter.
- **Same pattern elsewhere:** `combat_actions.go:1083` (`landDamage`), `:1806` (`AdjustCombatantHitPoints`), `combat_spells_hp.go:227`, `combat_traps.go:278`, `combat_death.go:245-253`, `combat_creatures.go:267` (dismissed creature that was acting, not tested).
- **Rules to respect:** idempotent `InTx` closures; undo must restore the state (`combat_undo.go:268-277` restores `Defeated`, so the turn state must be restorable or derived); docs "Joint turn" diagram already says the member leaves.
- **Risk:** a defeated NPC no longer ends its own turn: if it was the only acting member the turn must pass automatically. Guarded by `combat_joint_test.go`.

### U3-4 (announcement lost after commit)
- **Root cause:** publish happens on the request context after two reads, and a repeated key never publishes.
- **Where:** `combat_write.go` `finish`/`write`: publish from a context detached from cancellation (`context.WithoutCancel(ctx)`) and make the repeated path publish too (publishing is idempotent: hints with a revision). Alternative: only the detached context (smaller, but a failed read still loses it). I would do both.
- **Same pattern elsewhere:** every `s.finish` caller (`combat.go` 187, 587, 658, 727, 911, 977, 1047, 1130, 1179; `combat_actions.go` 791, 1034, 1327, 1437, 1661, 1823; `combat_spells.go:461`; `combat_death.go` 172, 266; `combat_undo.go:197`; `combat_opportunity.go:419`; `combat_theatre.go` 218, 328; `creature_cast.go:379`; `wildshape.go:474`) and the `!repeated` publishers `combat_actions.go:823`, `creature_cast.go:313`, `wildshape.go:481`, `traps_damage.go:218`, `traps.go:169-189`, `vitals.go:167`, `scene.go:723`, `progression/award.go:404`, `progression/undo.go:116`.
- **Rules to respect:** publish only after commit; never inside the `InTx` closure; docs "Game events".
- **Risk:** double hints on a replay (harmless, they say "read again"); `idempotency_test.go` checks answers, add a stream assertion.

### U3-5, U3-6, U3-7, U3-9 (hidden-NPC signals, RN-10)
- **Root cause:** "who may know this happened" is decided per call site, and several sites forget: the Shield event (target-only `Secret`), the fog hooks (`positionChanged`, `stamp`, `visibleRevision` ignore `Hidden`/`Secret`), the undo event (never stamped), the replay builders (`castProto`).
- **Where:** (1) `combat_reactions.go:251`: `Secret: secretOf(target, attacker)`. (2) `combat_fog.go`: skip `positionChanged` for a hidden mover; in `stamp`, treat an event with `Secret` as seen by nobody; `visibleRevision` should count only events in `seen_by` (or without `secret`). (3) `combat_undo.go`: copy `Fogged`/`SeenBy`/`Secret` from the undone event and make `publishLogChanged`/`publishEncounterChanged` follow them. (4) `castProto`: filter hits and pending by `v.sees` like `pendingFor`.
- **Same pattern elsewhere:** `combat_fog.go:505` callers `combat_move.go:511`, `combat_opportunity.go:566`, `combat_undo.go:202/207`; `combat_reactions.go:327` (`DeclineReaction`, harmless today); `RollAttack` replay `combat_actions.go:~1018` returns `AttackRoll.target_id`/outcome with no `v.sees` (code reading only); `combat_spells.go:~475` `SummonedCombatantIds` (not checked); `combat_cover.go`/`SetCombatantCover`/`SetCombatantSide` send `s.changed` for hidden NPCs (design-wide, documented as "hint"). Also `maps/fog.go:859-865` `CombatMoved` has no hidden parameter.
- **Rules to respect:** RN-10/RN-20; the player revision must never go down and must not rise from what they cannot see ("Per-player combat under fog"); leak tests in `docs/architecture.md` "Leak tests (RN-10)". Add the new tests there.
- **Risk:** hiding events from `visibleRevision` can make a revision stall while the player's copy is stale; `combat_fog_test.go` has the stream/revision tests.

### U3-8 (Action Surge twice)
- **Root cause:** no per-turn flag; the resource count is the only guard.
- **Where:** add `surged bool` reset in `ResetCombatantTurn` and set by `TakeAction`; or reuse a per-turn "feature used" set on the combatant. Disable the option in `GetTurnOptions` (rules `combatturn.go`) when set. Undo must clear it (`combat_undo.go` `eventActionTaken`).
- **Same pattern elsewhere:** other "once per turn" features (Sneak Attack is not modeled here); `feature:action-surge-2-uses` key has no handler (`combat_actions.go:1456`).
- **Rules to respect:** new migration (goose, run twice safe), sqlc regenerate, docs "Combat".
- **Risk:** the master may legitimately allow it: keep the master override like other economy checks.

### U3-10 (same key, another request)
- **Root cause:** `writeOnce` matches stored events by key + kind + actor only.
- **Where:** `combat_write.go`: add a request digest to `combatWrite` (like `startDigest`) stored in the payload and compared on replay; every handler passes `proto` fields minus the key. Alternative: store the digest in a new column `idempotency_digest` (migration) to avoid touching payloads; I would pick the column.
- **Same pattern elsewhere:** `creature_cast.go:313`, `wildshape.go:462`, `familiarsight.go:266`, `vitals.go:66-72`, `scene.go:618-627`, `:783-789`, `traps.go:183-187`, `traps_damage.go:160-165`, `traps_fire.go:201`, `:384-388`, `combat_theatre.go:117`; `puzzles_hints.go:120`, `puzzles_play.go:254` (not checked).
- **Rules to respect:** `invalid_argument` per "Error codes"; docs line "another change's key is `invalid_argument`".
- **Risk:** clients that resend a changed body with the same key would start failing; the web app builds a key per action (`idempotency_test.go`).

### U3-12 (Shield and several awaiting hits)
- **Root cause:** the Shield bonus is evaluated against one pending hit; other hits and later rolls use the AC stored when they were opened.
- **Where:** in `UseReaction`, after setting `AcBonus`, re-compare every other `AWAITING_REACTION`/`AWAITING_ROLL` pending of that target with `attack_total < attack_ac + 5` and discard them (restore on undo, `combat_undo.go:581-591`); or block `RollAttack` on a target that already has a hit awaiting a reaction. I would pick the re-compare (works for the NPC's multi-attack).
- **Same pattern elsewhere:** `DeclineReaction` (`combat_reactions.go:320`), `RollDamage` (`combat_actions.go:927`), multi-hit spell attacks via `combat_spells.go:602`.
- **Rules to respect:** RN-20 (the attack total never leaves the server), idempotent closure, undo restores every discarded pending.
- **Risk:** undo of Shield must restore all discards (`TestShieldTurnsAHitIntoAMiss`, `combat_spells_test.go:707`).

- **Same pattern elsewhere:** all 5 reach weapons in `equipment.json` (glaive `:253-267`, halberd, lance, pike, whip); `content.go:680-690` equipment view; `combat_opportunity.go:112` hardcodes 5 ft for the non-exact warning.

### U3-14 (undo stuck after a sheet edit)

- **Where:** `combat_undo.go` `takeBack`: for delta -1 skip a missing resource/slot (like `putVitals` cuts HP to the new max), or give `spendResource`/`spendSlot` a "restore" mode that clamps. Never return a plain `fmt.Errorf` for a state a client can cause.
- **Same pattern elsewhere:** `combat_undo.go:466`, `:503`, `:572`, `wildshape.go:510`.
- **Rules to respect:** `Error codes` (no 500 for client-caused state).
- **Risk:** silently skipping a restore; log at WARN without ids/names. Guarded by `TestUndoOfAppliedDamageSurvivesALowerMaximum`.

### U3-15 (offer survives a side change)

- **Rules to respect:** undo of `side_set` should restore the offers (or accept that it does not).
- **Risk:** small; `TestMR034_SidesAndTheMastersMarks`.
