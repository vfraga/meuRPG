# Review of unit 12: the live session's combat screens

- **Scope:** `web/src/app/pages/live-session/combat/` and everything under it (about 17,900 lines of TypeScript and templates, specs excluded), plus `core/combat` as far as the screens read it.
- **Commit reviewed:** `ae40f74` (`main` of the fork).
- **Time spent:** about 1 h 20 min (four parallel finders, then one verifier per candidate).
- **Models:** the session and the four finder subagents ran on `claude-sonnet-5-5` (Sonnet 5.5); the verification subagents were started with model `sonnet`. U12-15 was re-run by the main session because its verifier could not get a test run through.
- **Result:** 25 candidates, 22 confirmed by a failing Vitest spec (27 failing tests), 3 refuted, plus 5 smaller points left unverified (listed below the table). No production code was changed. No critical or high finding; the worst are medium.
- **How to run all the proofs:** `cd web && npx ng test --watch=false --include 'src/app/**/review12-*.spec.ts'` → `Test Files 22 failed (22) / Tests 27 failed (27)`. Each row below gives its own spec. Run a single one with `--include '<spec path>'`. Run them one at a time or in one invocation: several parallel `ng test` builds exhaust the 16 GB of the review box.
- Convention: all spec files are in `web/src/app/…`; paths below are relative to `web/src/app/pages/live-session/combat/` unless they start with `core/`. "Server replays by key" means `backend/internal/play/combat_write.go:241-259`: a repeated idempotency key with the same event kind and actor returns the stored answer and **never compares the request body**; the same key with another kind gives `invalid_argument`.

## Unverified points (not reported as findings)

- **U12-18(b)**: `OrderList` closes its "Remover"/"Esconder"/"Aliado"/cover questions and emits, but `combat-view.ts:1139` `run()` returns `false` silently when the page is `busy`; the master believes the action happened. Real by reading (`order-list.ts:363-368`, `order-list.html:243` has no `[disabled]="busy()"`), no spec written. A CombatView-level spec that calls `remove()` with `busy=true` would settle it.
- **U12-07 end to end**: the spec proves the sheet closes while its request is in flight; the second call and the spent slot/attack were not run through a two-sheet spec or the stack.
- **U12-17, landing squares outside `reachable`**: a jump over difficult terrain or creatures can land where the walk response has no square, so neither the warning nor the known-trap question (`move-page.ts:312-320`, `combat_traps.go` `markKnownTraps`, reachable squares only) can be shown without a new server field (server side, belongs to the backend units).
- **U12-03 secondary**: a double tap on "Próximo turno" landing after the first response is applied ends the next turn (`run()` builds the expected id from the fresh encounter). Possibly by design; the comment "a double tap never skips two turns" overstates it. An e2e with a slow response would settle it.
- **Spell details cache** (`core/combat/spell-catalog.ts:23-38`, never invalidated; `live-session.ts` sets no `onContentChanged`): players keep the old attack/save/heal flow after the master edits table content mid-session. Needs a check of which spell mechanics table content can override.
- **Accuracy of "Você é o próximo"** (`turn-panel`): `nextCombatant`/`playsBefore` work on the player's filtered list, so a hidden NPC between players can make the banner wrong. No hidden data is shown.
- **Enter vs busy in `player-initiative/player-initiative.html:75`** (`confirm()` checks only `face !== null`): the same gap as U12-14(B) for a player, read not run.

## Fix directions

Common to every idempotency-key finding (U12-10, 11, 12, 13, 21): the project rule is `docs/architecture.md` rule 9 (lines 100-101): one key **per action**, kept on retry, renewed on success or when the values change; the tool is `ActionKey.keyFor(what)` / `renew()` in `web/src/app/core/connect/idempotency.ts` (already used by `shared/monsters/put-sheet/put-sheet.ts:205` and `SpendMovement`). Because the server replays by kind+actor without comparing the body, a key that survives a change of intent is silently wrong, not an error. No new dependency; no docs change beyond the keyed method's doc comment.

**U12-01.** Root cause: `stageAfterRoll` only knows `AWAITING_ROLL`; the result card treats null damage as a miss. Fix in `core/combat/attack-flow.ts` (`stageAfterRoll`, a `waiting` stage or flag for `AWAITING_REACTION`) and `attack-result.ts` (show "Esperando a reação do alvo" instead of "Sem dano"). Model: `attack-flow.ts:151,165` (`pendingNote`) and `npc-card/pending-damages.html:68`. Same pattern: the `done` branch of `attack-sheet.html:~141-155` shows `after()`/`spent()` only. Rules: RN-20 (the attacker must not learn the total), `architecture.md:1640` "The reaction: Shield". Risk: the attacker's `RollDamage` only exists once the pending moves to `AWAITING_ROLL`; guard with `attack-flow.spec`, `attack-sheet.spec`.

**U12-03.** Root cause: the confirm is not bound to the turn it was asked about. Fix in `combat-bar/next-turn.ts` and `combat-view.ts` `nextTurn`: either (1, pick this) have `NextTurn` clear `asking` in an effect when `pendingNote`/`waiting`/`busy`/the current combatant changes and guard `confirm()` the same way, or (2) capture `who` and `round` when the question opens and send them with the confirm (stricter, needs a signature change on `next`). Same pattern: `turn-panel/end-turn.ts:130`, `turn-panel/turn-bar.ts:125`, `joint-turn/end-part.ts:147`, `creature-turn/creature-bar.ts:67` (each keeps an inline `asking`; check each; `endPart` already takes an explicit id). Rules: the server's `expected_combatant_id`/`expected_round` guard only works if the client sends what the user saw. Risk: `next-turn.spec`, `combat-view.theatre.spec` guard the normal flow.

**U12-04.** Root cause: `verdict()` maps "no data" to `beyond`. Fix in `move-page/move-page.ts`: a third verdict kind `unknown` when `optionsFailed()` (and while the first answer is pending) that lets `canMove` pass and sends the walk, showing the server's refusal (`serverError`); in `core/combat/move-options-state.ts` keep the last good `data` on a failed refresh. Same pattern: `summary()` `:150-153` turns `beyond` into "Longe demais". Rules: `architecture.md` "Movement and opportunity attacks on screen" (~1853-1855): the browser computes no cost or reach. Risk: `move-page.spec` line ~229 ("still lets the server judge") only asserts the text; extend it.

**U12-05.** Root cause: `runMove` returns a boolean, so `confirmJump` cannot see `stoppedEarly`. Fix in `combat-view.ts`: return the `MoveResult` from `runMove` (or test `moveNote()` non-empty) and set "saltou" only when the square changed. Keep the note generic: the comment at `:2084` says the blocker must not be named (RN-10). Same pattern: none (`confirmMove` sets no note). Risk: existing `combat-view` move specs.

**U12-06.** Root cause: `RollPicker.text` is component-local and the cast sheet keeps one picker alive while its range changes. Fix in `cast-sheet/cast-sheet.ts`: call `picker.reset()` in `pickSlot`, `toggle` and `deal` (as `npc-card.ts:321` does), or key the picker with `@if/@for` on slot+targets.
