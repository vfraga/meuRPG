# Rules content (SRD)

The rules content is data: an imported snapshot of the SRD 5.1 plus handwritten effects, names and texts, embedded in the binary.
This page says where each file lives, which tests guard it and how to change it.
How the engine reads the content is in [Architecture](architecture/rules.md); the decision to keep it as versioned data is ADR-0008.

The `rules` module is pure: its tests need no database, Docker or network and run in seconds, so they are the fast loop for working on the engine, the effects and the names (commands in [Testing](testing.md#go-unit-and-characterization-tests)).

## Layout

Everything is under `backend/internal/rules/srd51`.

| Folder | What it is | Who writes it |
| --- | --- | --- |
| `data/` | The snapshot of the SRD 5.1 in our normalized format (classes, spells, monsters, magic items...), with `manifest.json` holding the sha256 of each file | Generated by `cmd/srdimport`. Never edited by hand: `TestSnapshot` compares each file with the manifest |
| `effects/` | What the engine applies for each feature, trait, spell and item; the Portuguese names and texts; corrections to the snapshot; our own tables | Handwritten |

The importer reads the 5e-database (`packages/5e-database/src/2014/en` of the `5e-bits/5e-srd-api` repository) at a pinned commit (`sourceCommit` in `backend/cmd/srdimport/main.go`, repeated in `NOTICE`), and refuses any input file whose sha256 is not in its `inputHashes` table.
A creature's vulnerability, resistance or immunity entry in `monsters.json` has `types` (damage type keys), `note` (the rest of the SRD's words, kept for display) and `qualifier`, which the importer reads from the note: `nonmagical`, `nonmagical-unless-silvered` or `nonmagical-unless-adamantine` for the entries limited to nonmagical attacks, empty otherwise. The engine applies `nonmagical` and leaves the two material qualifiers to the master.
It also refuses totals the SRD fixes (334 creatures, 362 magic items) and malformed shapes, such as a spell area that is not a cone, cube, cylinder, line or sphere or a size that is not a multiple of 5 feet; loading in `rules` checks everything again.

No text from a book outside the SRD enters the repository, which is public.
Names and texts in `effects/` are ours, in Portuguese; third-party content is credited in `NOTICE`.

## Updating the SRD to a new commit

1. Download the JSON files at the new commit into a folder outside the repository:

   ```bash
   git clone --filter=blob:none --no-checkout https://github.com/5e-bits/5e-srd-api.git /tmp/5e-srd-api
   git -C /tmp/5e-srd-api sparse-checkout set --no-cone packages/5e-database/src/2014/en
   git -C /tmp/5e-srd-api checkout <commit>
   ```

2. In `backend/cmd/srdimport/main.go`, change `sourceCommit` and the `inputHashes` table (`shasum -a 256 /tmp/5e-srd-api/packages/5e-database/src/2014/en/5e-SRD-*.json`).
3. Generate the snapshot: `cd backend && go run ./cmd/srdimport -src /tmp/5e-srd-api/packages/5e-database/src/2014/en`.
4. Change the commit in `NOTICE` (`TestSnapshot` checks it).
5. Run `go test ./internal/rules/...`. `TestReferences` shows broken references, `TestEffectsCoverLevels1To5` and `TestNamesPT` show what was left without an effect or a name, and the golden test shows the numbers that changed.

## Changing an effect, a name or a text

**A content version never changes in place** (ADR-0008): saved characters and table content refer to a version string `srd51@<commit>+fx.<n>`.
After you edit any file in `effects/`, `TestSnapshot` fails and prints the new `revision` and `sha256` to put in `effects/revision.json`; `n` is that revision.
A change to `data/` follows the same rule, but `TestSnapshot` only hashes `effects/`, so raise the revision by hand with the same `sha256`.
The history of what each revision changed is `git log` on `effects/revision.json`.

- **Effect types are closed**, and loading refuses everything else. The effect types, modifier targets, modes, senses and handlers are the `effectTypes` and neighbouring lists in `backend/internal/rules/effects.go`; the limits are the constants below them. Content can only name a handler; it never brings code.
- **Formulas** use only `level()`, `classLevel("wizard")`, `mod("int")`, `score("int")`, `prof()`, `armor()`, `shield()`, `floor`, `ceil`, `min` and `max`, and, in a condition of table content, `active("name")` (`backend/internal/rules/formula`). `FuzzCompileFormula` guards the compiler.
- **Resources** recharge as `short_rest`, `long_rest`, `dawn`, `none`, `initiative`, `restore_one_on_short_rest` or `restore_one_on_long_rest`, and may carry `recharge_if` (a Bool formula) and `recharge_then` together, to recharge differently from a level on. A `modifier` on a score (`score.str`...) is an `add` with a `cap` above 20. `save.all` is a modifier target.
- **`replaces`**, on a higher tier of a scaling feature (Channel Divinity twice between rests, Extra Attack 2, the Bardic Inspiration die...), names the lower tier's feature key: the sheet lists only the newest tier, while the lower one's effects still count. It takes that key and nothing else.
- **`grant_action`** may carry `resource`, the key of a resource of another feature that each use spends (the monk's ki actions); without that resource at the character's level the action is not offered. Table content may add `cost`, `cost_max`, `value_per_point`, `heal`, `temp_hp` and `ability` (see [Costs, healing actions and hooks](architecture/rules-table-content.md#costs-healing-actions-and-hooks)); the SRD's own effects use none of them.
- **`on_event`** is table content's alone: a hook of the owner on `short_rest`, `long_rest`, `death_save_failed` or `drop_to_zero`.
- **`wild_shape`** sets the limits of Wild Shape: `max_cr` or `max_cr_from`, `no_fly`, `no_swim`, `form_cost` and `magical_attacks`.
  Loading refuses other fields and a `max_cr` that is not a CR.
  It takes effect on a character with Wild Shape and at least one effect that sets a rating.
- **`slot_recovery`** lets a feature use recover spell slots: `resource`, `recover_max_level` and `recover_levels`.
  `grant_action` also takes `gives_slot` and `spends_slot`.

## The effect files

| File | Holds | Loading refuses |
| --- | --- | --- |
| `<class>.json`, `races.json`, `backgrounds.json`, `feats.json` | The effects of each feature, trait, background and feat (`feat:grappler`...) | An unknown type or field; an entry that is not in `data/`; a prerequisite with an unknown ability, proficiency or race; an `ability_increase` that is not a whole 1 or 2 on distinct abilities |
| `names_pt.json` | The Portuguese names, by key (`item:<index>`, `monster:<index>`, `resource:<name>`, `trap:<key>`, `light:<key>`, `attunement:<restriction>`, `attack:<SRD name>`...) | A missing name where a test asks for one (`TestNamesPT`, `TestMagicItemNamesPT`, `TestAttackNamesPT`, `TestActionNamesPT`); an `attack:` key that no creature's action uses; duplicates among spells, creatures, items, races, classes, subclasses or backgrounds (`TestNamesPTAreUnique`) |
| `advancement.json` | The XP of each level (1 to 20) and of each challenge rating (0 to 30) | A table out of format |
| `encounter_budget.json` | The SRD 5.2.1 "XP Budget per Character" table: per level, the low, moderate and high bands | A missing or out-of-order level, a row that does not grow, an unknown field |
| `magic_item_values.json` | The value in gp of each rarity and the consumable divisor, from the SRD 5.2.1 "Magic Item Rarities and Values" table (the artefact has no price) | A rarity without a value, values that do not rise, a value for the artefact, a divisor below 1 |
| `standard_actions.json` | The actions every character has (Attack, Dash...) | |
| `spells.json` | What the spells that read hit points do, by `kind`; see [below](#spell-effects) | See below |
| `spell_targets.json` | The target of the SRD spells where the structured area or the text is wrong (`creature`, `creatures` with a number, `area`, `self`, `none`, and `label_pt`) | A key that is not an SRD spell; an unknown type |
| `combat_effects.json` | The effects that last: the conditions and who reads each, and spells such as Bless, Haste and Hold Person as effects with a duration, the clock in rounds, end-of-turn saves and exhaustion | |
| `damage_resistances.json` | Resistances by race or feature, each with its `source`, and the state it needs (`while: "rage"`). The same resistance from two sources counts once | An unknown damage type or source, an unknown field |
| `choices.json` | The data of the class and race choices (RN-33): the Draconic Ancestry table, the breath weapon, the prerequisites of the invocations, Favored Enemy types, Natural Explorer terrains, racial resistances, one Portuguese line per option, each row with its SRD source | A row without source, a key the content lacks, a bad shape, an option without its line (`TestChoiceDataIsClosed`) |
| `traps.json` | The SRD's example traps with its severity tables. Each has `kind`, `description_pt` (our words), the DC to notice and to find (the find DC is ours where the SRD gives none, marked `find_dc_ours`), the `trigger`, `area_size`, `targets` and the parts of the effect (`attack`, `damage`, `conditions`, `save`) | An unknown field, condition or damage type; a save without an ability; "half" without damage; a pit whose fall is not 1d6 per 10 ft; a trap without a name in `names_pt.json` |
| `lights.json` | The SRD lights in feet (`bright_ft`, `dim_ft`). The bullseye lantern is left out: the app only lights circles | A radius that is zero, negative or not a multiple of 5 ft; a light without a name or duration |
| `treasure.json` | **Our own tables** for the treasure generator (MR-044): the value steps and Portuguese names of gems and art objects, and per party-level band the coins, the hoard and how many gems, art objects and magic items | A band that leaves a level out, an unreadable roll, an unknown coin, step or rarity, a repeated name, a step above 10,000 gp, a name over 60 characters, a treasure over the piece limits |
| `consumables.json` | The single-use magic item categories and items | An item the content lacks |
| `corrections.json` | Fixes to what the 5e-database lacks or gets wrong, each with its `source`; see [below](#corrections) | See below |
| `*_pt.json` for texts | The Portuguese texts; see [below](#portuguese-names-and-texts) | See below |
| `revision.json` | The revision and the hash of the other files in `effects/` | |

SRD 5.1 has no random treasure tables, so the numbers and names in `treasure.json` are ours, with no book or other-site table.
Changing a treasure table or an item name changes the treasure of every seed (`TestTreasureGolden` warns), so the revision goes up: a seed is only valid within one content version.
Only the SRD 5.1 content and three SRD 5.2.1 tables (the XP budget, the ways to make ability scores and the magic item values) are used; the 5.2.1 ones are credited in `NOTICE` and labelled "SRD 5.2.1 (regras de 2024)" on screen.
A spell or trap outside the SRD never enters.

### Spell effects

`effects/spells.json` gives each entry a `kind`; the kinds are the `SpellKind*` constants in `backend/internal/rules/spelleffects.go`:

- `hp_pool`, `hp_threshold`, `zero_hp_target`, `flat_heal`, `temp_hp` and `max_hp` read hit points (see [Architecture](architecture/play/casting.md#spells-that-read-hp)); a spell of one of these kinds also needs a computation in `rules/combat/hpspells.go` and its test.
- `ignores_cover` (no other fields) marks a spell whose saving throw gets no cover bonus; `Content.IgnoresCover` answers it.
- `revive` takes `hit_points`, `window_rounds` and `source` and nothing else; `Content.Revive` answers it and `play` casts it.
- `summon` lists the creatures (`creatures`, with `count`, `count_per_level` and what each may do: `attack` is `none`, `reaction` or `full`; `unlocks` for a feature such as Pact of the Chain) or gives CR bands of a type (`type`, `options` with `count` and `max_cr`, `multiplier_at_level`). A new spell of this kind needs its test in `rules/summon_test.go`.

Loading refuses a spell that is not from the SRD, an unknown kind, a field the kind does not use, a condition that does not exist, a creature that does not exist, a CR that is not from the SRD and a creature type that is not one.
The casting time, ritual and concentration come from the spell, not from this file.

### Corrections

`effects/corrections.json` fixes what the snapshot gets wrong or lacks against the tables and text of SRD 5.1, each entry with its `source` line.
Its sections are `corrections` (class table columns), `multiclass_corrections`, `creature_corrections`, `spell_corrections`, `subclass_corrections`, `expanded_list_corrections`, `spell_list_corrections` and `subclass_feature_corrections`.

- `creature_corrections` set closed fields of a stat block, one value each: `attacks_per_action`, `armor_class`, `hit_points` with `hit_points_roll`, the speeds (0 removes one), the senses, `passive_perception`, `skills`, `damage_immunities` and `condition_immunities`, and, with an `action` naming one of the stat block's actions, `action_save_success` (what that action's saving throw does on a success: `half`, `none` or `other`; see [Creatures](architecture/rules-creatures-items.md#the-actions-of-a-stat-block)). `TestMultiattackCountsFollowTheSRDText` reads the Multiattack text of every creature and checks the engine's number, with an explicit list of the ones the text does not let it read.
- `spell_corrections` give a spell an `attack_type`, a saving throw (`save_ability` with `save_success`: `half`, `none` or `other`) and a `damage` table by slot level that replaces the snapshot's. A spell whose effect comes on later turns or on a trigger gets its dice recorded without a saving throw, so a cast does not roll it at once. `damage_choice` says what the caster picks among a spell's damage types: `scale` (every type is dealt and the higher-slot dice go to the picked one) or `alternative` (only the picked one is dealt).
- `spell_list_corrections` add spells to or remove them from a class's list; `subclass_feature_corrections` add features to a subclass row at a class level, creating the row when the snapshot has none; `subclass_corrections` add spells a subclass always has; `expanded_list_corrections` mark a subclass whose spells only join the class list to choose from.

The loader applies the corrections over the snapshot and refuses an unknown class, creature, spell, subclass, field or level, a value that does not fit its field, a repeated correction and a correction without a source (`TestCorrectionsAreClosed` and its siblings in `snapshot_test.go`).

### Portuguese names and texts

**Names** (`names_pt.json`) follow the official terms of the Brazilian editions of the Player's Handbook and the Dungeon Master's Guide (names and short terms only, never the books' text), with two exceptions: the product owner's choice ("Derrubado" for Prone) and the SRD 5.1 name when the official one carries a proper name the SRD removed ("Esfera Congelante", not "... de Otiluke").
A new or renamed entry checks its name against the [glossary](product/glossary.md).
The app's text uses the same terms: "habilidade" for ability (never "atributo"), "nível da magia" or "1º nível" for a spell level (never "círculo"), and "teste de resistência" for a saving throw (never "salvaguarda").
The browser keeps a list of the condition names in `web/src/app/core/combat/conditions.ts`: when a name changes in `names_pt.json`, change it there too.
The Portuguese names of creature actions are `attack:<SRD name in lower case, with hyphens>`, whether or not the action rolls an attack (the prefix is older than the breath weapons, Multiattack or Change Shape that share it); the action text stays the SRD's English.
Every attack has one (`TestAttackNamesPT`) and so does every action of every creature (`TestActionNamesPT`: Sopro de fogo, Ataques múltiplos, Presença aterradora...), because the master's card and the combat log show it.
The test names the creature and the action that lacks one.
A new action takes its name by adding its `attack:` key to `names_pt.json`, which raises `effects/revision.json`.
The names follow the style of the attacks: the first word capitalised, the plural kept ("Garras"), a variant in parentheses translated whole ("Garra (Mordida na forma de fera)").
**Backlog:** the names of traits, reactions and legendary actions still show the SRD's English name: the browser shows them only on the stat block, in English by design. A reaction or legendary action that only a low-rating creature has (Parry, Shriek, Split, Heal Self, Shimmering Shield) is in that group.
The browser shows a usage text ("Recharge 5-6") in Portuguese through `usageText` (`web/src/app/core/combat/creature-action.ts`): "Recarga 5–6", "3/dia", "Recarrega após um descanso curto ou longo".

**Texts** are in `spells_pt.json`, `magic_items_pt.json`, `features_pt.json`, `traits_pt.json`, `backgrounds_pt.json` and `feats_pt.json`, keyed `spell:<index>`, `item:<index>`, `feature:<index>`, `trait:<index>`, `background-feature:<index>` and `feat:<index>`.
They are **our own translation of the SRD 5.1 English text in `data/`**, an adaptation as CC BY 4.0 allows (credited in `NOTICE` and on the "Créditos" page):

- written from the English alone, in our own words, **never** from the Brazilian books or any publisher's text; only names and short terms follow the official terms;
- metric units, as the app shows them (5 ft = 1,5 m; 1 lb = 0,5 kg; decimal comma, thousands dot);
- the markdown is kept as it is (bold, italics, `- ` lists, `|` tables with the same columns and rows).

Loading is strict: a key that is not an SRD entry of the file's kind, a JSON field the format does not know, a paragraph count different from the English one, an empty paragraph, and a `material` on a spell without a material component (or one without a `material`) refuse to load.
An entry a file lacks falls back to the English on the screen, flagged (`text_pt_missing`, `description_pt_missing`, `desc_pt_missing` in the API); `TestTextsPTCoverEverySpellAndItem` and `TestRuleTextsPTCoverEverySRDEntry` fail while any entry lacks its text.
The screen shows the Portuguese first with a "Ver em inglês" button (see [Architecture](architecture/rules.md#portuguese-texts-of-the-srd)).
