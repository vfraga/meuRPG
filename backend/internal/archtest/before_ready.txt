# The tests `make before-ready` runs (docs/testing.md#before-ready): the tests that compare
# against a stored file or against literals the project froze (names with Frozen or Golden:
# goldens, hashes, frozen tables, refusal messages, stored fixtures) and the inventory tests that
# list the service methods, the error reasons, the authorization matrices and the event kinds. A branch that changes any of what they compare
# makes them stale, so a session runs them before it writes `ready:`.
#
# One tab-separated line each (an editor that turns tabs into spaces breaks the line, and
# TestBeforeReadyListIsWhole says so):
#
#   run<TAB>package<TAB>-run regex<TAB>how to regenerate<TAB>inputs
#   helper<TAB>package<TAB>function<TAB>why   a function whose callers compare with a file
#
# package is the directory under backend/ ("." never: a package with no tests is not listed).
# The regex is the argument of `go test -run` for that package: anchor names with ^( | )$, or
# use the naming convention the package keeps. {test} in the last column is the name of the
# test that failed. A test that turns a second train round red is added here.
# TestBeforeReadyListIsWhole fails for a test that reads a golden, hash or fixture file
# (a ".golden", ".sha256" or "testdata" literal or a constant holding one, goldentest.Compare/JSON,
# a flag.Bool, a variable named frozen* or *Golden) and is on no line of its package, and for a
# line that matches nothing.
#
# inputs is what the line's tests read outside their own package directory and outside the
# packages they import: comma-separated paths from the repository root (a file, or a directory
# with everything under it), or - for none. The default run of `make before-ready` runs a line
# when the change touches its package, a package it imports, or one of its inputs
# (docs/testing.md#before-ready); TestBeforeReadyInputsAreComplete fails for a "../" path
# that a listed test reads and the line does not name.
